# 駐車場マップ管理アプリ

卒業研究「駐車場空き区画案内」の**管理者用Webアプリ**です。利用者向け画面とは別リポジトリで管理し、施設ごとの駐車場配置データを作成します。

## 役割

管理者が航空写真を下敷きにして駐車場の形状を作成し、駐車区画・道路・建物・出入口・設備を登録します。保存したレイアウトは `facilityId` をキーに利用者アプリへ渡します。

利用者向けの施設検索・区画検索画面は、このリポジトリには含めません。

## ファイル構成

| ファイル | 役割 |
| --- | --- |
| `index.html` | 管理画面の3ペインUI、航空写真設定、クラウド同期UI |
| `admin.css` | 管理画面専用スタイル、オブジェクト別表示、ダークモード |
| `admin.js` | レイアウト編集、ドラッグ、航空写真、保存、入出力、自動同期 |
| `facility-catalog.js` | 管理画面用の研究対象120店舗マスター |
| `facility-catalog.json` | 同じ施設マスターのJSON版。JSON仕様上コメントは書けない |
| `sync-config.js` | Supabaseの公開URL・公開用キー設定 |
| `supabase-setup.sql` | 自動反映用テーブルとRLSを作成するSQL |

## 建物出入口の仕様

建物出入口は駐車場出入口とは別オブジェクトです。

```js
{
  uid: "entrance_001",
  objectType: "buildingEntrance",
  name: "店舗正面入口",
  entranceType: "main",
  x: 520,
  y: 160,
  rotation: 0,
  publicAccess: true,
  wheelchairAccessible: true,
  guideTarget: true,
  buildingId: "building_001"
}
```

`guideTarget: true` の入口は、利用者アプリが「入口に近い」区画を選ぶときの基準にできます。

## 航空写真を下敷きにした編集

管理画面は国土地理院「全国最新写真（シームレス）」のXYZタイルを編集用背景として表示できます。

保存するのは次の設定だけで、航空写真そのものは保存しません。

```js
background: {
  type: "gsi-seamlessphoto",
  centerLat: 34.6998,
  centerLng: 133.9280,
  zoom: 18,
  opacity: 0.75
}
```

緯度・経度・ズームを合わせた後、その上から区画や道路を配置します。航空写真を利用する画面では出典表示を残してください。

## 座標と縮尺

`x` / `y` はブラウザー画面上の一時的な座標ではなく、施設ごとの編集キャンバス上の論理座標です。

`canvas.scaleMetersPerPixel` を設定すると、利用者アプリで入口までのレイアウト距離をメートルへ換算できます。

## 保存

### 端末内保存

通常編集は `localStorage` の `parkingAdminLayoutsV1` に保存します。ブラウザーのデータを削除すると消えるため、JSONバックアップも利用してください。

### JSON

- **JSON出力**：全施設の編集データをバックアップ
- **JSON読込**：バックアップした全施設データを復元

### parking-layouts.js

クラウド同期を使用しない場合の互換用です。出力した `parking-layouts.js` を利用者アプリへ配置すると手動反映できます。

## 自動反映（Supabase）

構成は次のとおりです。

```text
管理画面
  ↓ 管理者ログイン
Supabase parking_layouts
  ↓ 匿名ユーザーは読み取りのみ
利用者アプリ
```

管理画面でログイン中は、編集後およそ1秒で現在施設のレイアウトを自動保存します。利用者アプリは区画検索前に最新データを取得します。

### 初回設定

1. Supabaseプロジェクトを作成
2. `supabase-setup.sql` をSQL Editorで実行
3. Authenticationで管理者ユーザーを作成
4. `sync-config.js` に Project URL と **publishable key / anon key** を設定
5. `enabled: true` に変更
6. 管理画面で管理者メール・パスワードを入力してログイン

**service_role / secret key はブラウザーのコードへ絶対に記載しないでください。**

## レイアウトデータの基本形

```js
{
  schemaVersion: 1,
  facilityId: "target_021",
  canvas: {
    width: 1000,
    height: 700,
    scaleMetersPerPixel: null
  },
  background: null,
  objects: []
}
```

`facilityId` は管理アプリと利用者アプリを結ぶ固定キーです。店舗名を変更しても、既存レイアウトを維持したい場合はIDを変えないでください。

## コメント方針

第三者が卒業研究のコードを確認できるよう、次の方針でコメントを記載しています。

- ファイル冒頭：そのファイルの責務とデータフロー
- JavaScript：関数の目的を `/** ... */` で記載
- 分岐や安全上の理由：通常コメントで「なぜ必要か」を補足
- HTML：各画面・ペインの役割をコメント
- CSS：テーマ・レイアウト・オブジェクト表示など意味単位でコメント
- JSON：仕様上コメント不可のためREADMEとJS版データに説明を記載

## 現時点の制限

- 航空写真は編集用の下敷きで、ユーザーアプリにはそのまま表示しません。
- 一方通行・進入禁止等は保存・表示できますが、経路探索にはまだ反映していません。
- 空き状態は研究用データで、実店舗のカメラ判定とはまだ接続していません。


## 管理画面の直接操作

数値入力を主操作にせず、PowerPointに近い操作を基本にしています。

### オブジェクト

1. 枠をクリックして選択
2. 枠本体をドラッグして移動
3. 選択枠の周囲に表示される8個の白いハンドルをドラッグしてサイズ変更
4. 上部の「↶ 90°」「↷ 90°」で回転
5. 必要な場合だけ右側の「数値で微調整」を開く

「枠を吸着」がONの場合、5pxグリッドと近くの枠の端・中心へ自動で揃います。配置時には補助線を表示します。

キーボードでは、矢印キーで1px、Shift＋矢印キーで10px移動できます。Ctrl/Cmd＋Dで複製、Deleteで削除できます。

### 駐車区画の連続生成

駐車区画を1つ選択し、右側の「連続数」を指定して「上・下・左・右」を押すと、選択枠と同じ大きさ・向きの区画を隙間なく連続生成します。

90°回転した区画でも、区画自身の向きを基準に上下左右へ並べます。

### 航空写真

緯度・経度を毎回入力する必要はありません。

1. 「航空写真を表示」
2. 「写真を動かす」
3. キャンバス上の写真をドラッグして位置調整
4. マウスホイールまたは「＋／－」でズーム
5. 「写真調整を終了」で区画編集へ戻る

緯度・経度の直接入力は詳細設定として残しています。航空写真は国土地理院の「全国最新写真（シームレス）」を使用し、画像そのものは保存しません。


### 編集倍率

航空写真タイル自体の最大ズームは18ですが、管理画面の編集倍率は独立して**25%～12800%**まで変更できます。

- 「＋／－」：段階的に拡大・縮小
- スライダー：25%～12800%
- 「全体表示」：キャンバス全体が見える倍率へ戻す

編集倍率は表示だけを変えるため、保存される `x / y / width / height` は変化しません。高倍率で数px単位の白線合わせができます。

### 施設選択時の航空写真

施設を選択すると、次の順でその施設付近を航空写真の中心にします。

1. 公式MAP等から確認済みの緯度経度があれば、その固定座標
2. 固定座標がない場合は、2026-09-28に監査した確認済み住所を国土地理院の住所検索へ渡す
3. 住所検索できない場合のみ、緯度経度の直接指定

旧版の「都道府県＋店舗名の先頭検索結果」を自動採用する方式は廃止しました。同名店舗・類似施設へ飛ぶ可能性があるためです。

管理者が航空写真を手動で動かした後は `manuallyAdjusted: true` を保存し、通常の施設切替では自動上書きしません。「店舗位置へ戻す」を押した場合だけ確認済み所在地へ戻します。

### 駐車区画の路面標示

駐車区画の外形と、実際に路面へ引かれた線を別々に管理します。

対応する形：

- 四辺・一本線
- コの字
- 両側線のみ
- 頭側だけ
- 頭側の短い印
- 左側／右側一本線
- 四辺・二重線
- 両側・二重線
- 四隅L字
- 区画線なし

線色と太さも保存します。「頭側」は区画のローカル上辺で、回転すると路面標示も同じ向きへ回転します。連続生成した区画にも同じ線設定を引き継ぎます。


### 航空写真が一部欠ける場合

「全国最新写真（シームレス）」の高倍率タイルが取得できない場所でも編集を継続できるよう、背景描画には自動フォールバックを入れています。

```text
ズーム18を取得
  ↓ 取得できない
ズーム17の同じ場所を拡大
  ↓ 取得できない
16 → 15 → 14
```

また、キャンバス外周へ1タイル分余分に読み込み、タイル同士を約1px重ねることで、ドラッグ時やブラウザーの丸め誤差による白い隙間を防ぎます。

低いズームへフォールバックした場所は、写真自体の元解像度が低くなるため細部はぼやけますが、背景が部分的に空白になることを避けられます。


## 店舗所在地の監査

2026-09-28に研究対象120店舗の所在地データを再監査しました。

- 120 / 120店舗：確認済み住所を登録
- 公式MAPから座標を直接確認できた店舗：固定緯度経度を登録
- その他：確認済み住所を国土地理院住所検索へ渡して位置決定
- 位置情報の出典種別・確認日を施設データへ保存
- 旧版の店舗名検索による自動位置は、確認済み所在地へ補正

`target_041` のトライアル山口小郡店は、2026-09-28時点で**2026年11月中オープン予定**のため、`operatingStatus: "opening-scheduled"` として管理しています。

施設データの主な所在地項目：

```js
{
  address: "岡山県岡山市南区豊浜町13番68号",
  latitude: 34.63085566541993, // 公式MAP座標が確認できた場合
  longitude: 133.93570388945932,
  locationVerified: true,
  locationVerificationDate: "2026-09-28",
  locationSource: "TRIAL公式店舗情報",
  coordinateSource: "公式MAP座標",
  operatingStatus: "active"
}
```


### 店舗位置の精度

店舗選択時の位置決定は、誤った店舗や同名施設を表示しにくくするため次の優先順位にしています。

1. 個別確認済みの固定緯度・経度
2. 公式店舗情報で確認済みの住所を使った住所検索
3. 住所が無い場合のみ、都道府県・市区町村・店舗名による名称検索

名称検索は補助扱いです。最終的には研究対象120店舗すべてについて、正式住所と固定座標を確認して登録する方針です。

住所検索で取得した座標は「検索結果」であり、店舗敷地中心を人手で確認済みとは限らないため、`locationVerified: false` として背景情報へ記録します。
