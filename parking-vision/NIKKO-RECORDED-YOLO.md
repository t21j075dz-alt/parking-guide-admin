# 道の駅日光：録画映像からYOLOで可視区画すべてを逐次判定

2026-11-06 更新

## 仕組み

録画を仮想カメラとして読み込み、実カメラと同じYOLO車両検出・追跡・駐車状態・診断CSVを使用します。**8区画固定は廃止**しています。録画に完全に映るすべての区画を対象にできます。実際の道の駅日光の現在の空きとは区別します。

管理マップには画角外の駐車枠も残せますが、それらをYOLOの監視対象・空き案内・満空集計に含めません。部分的に映る区画や極小の区画も安全のため対象外にします。利用者画面には未確認と表示します。

## Gドライブの動画と、全アプリへのループ反映（2026-11-13）

- 動画は `G:\parking-movie` の `道の駅日光駐車場ライブカメラ_ニコニコ本陣_0533.mp4` を優先します。フォルダ内に別の動画が1本だけならそれを使用、複数なら番号選択、見つからなければ手動でパスを入力します。
- アップロードされた元動画は **1920×1080／30fps／約5分33秒** です。これは過去映像であり現地のライブカメラには接続しません。
- `道の駅日光_録画YOLOを開始.cmd` のメニュー **1** はPC内だけ、**2** はSupabaseを使って管理者・利用者アプリの区画状態へ反映します。メニュー2では、まず録画共有の確認を行い、その後「写真も共有」と明示した場合だけ**約5秒間隔のウォーターマーク付き録画静止画**も共有します。
- 別の画面・端末へ流れるのは区画の状態と明示承認した縮小静止画です。**30fpsの動画ストリーミングではありません**。管理者アプリのライブ監視は約4秒、利用者アプリの判定は約3秒、写真は約5秒で更新します。停止後は写真を非公開へ戻し、画面は20秒を超えた古い静止画を表示しません。
- `-Once` を指定しなければループします。新しい周回は追跡ID・駐車判定をリセットするため、前周の「空き」をそのまま引き継ぎません。
- `parking-vision/config.json` と映像原本は上書きせず、日光用の `config_nikko_video_demo.json` に区画校正を保存します。初回は映像上の区画位置の目視確認が必須です。

### 推奨：映像を基準に、ずれた駐車枠を個別に直す（2026-11-13）

道の駅日光の管理マップ（59区画）は模式図です。実画像とは各列の間隔や長さが異なる場合があるため、全体のホモグラフィだけで完全に一致させる必要はありません。次の2方式を使えます。

**方法A：自動配置＋個別補正（既に一括投影している場合）**
1. 管理者アプリ「カメラと地図を合わせる」で日光の録画静止画を開き、従来どおり全体を自動計算します（4～24点）。
2. 下の **「合わせ方」→「自動計算して、ずれた枠だけ補正」** を選びます。
3. 緑色の枠をクリックして対象を選ぶか、「写真と結び付ける駐車枠」から **管理マップの区画ID** を選びます。
4. **枠自体を写真上でドラッグして移動**、四隅の丸をドラッグして形を調整できます。大幅にずれている場合は「この枠の四隅を写真で指定」を押し、同じ白線の4角をクリックしてください。
5. 補正した区画は黄色で表示され、他の区画の位置は変わりません。元の管理マップにある区画番号・位置は変更しません。

**方法B：写真から直接登録（模式図と映像が大きく違う場合）**
1. 「合わせ方」→ **「地図の変換を使わず、写真から登録」** を選びます。
2. 管理マップ側の区画IDを選び、「この枠の四隅を写真で指定」→ 写真の白線を4回クリックします。座標はカメラ画像全体の相対位置で保持されます。
3. 必要な区画だけ繰り返します。写真の外にある区画は登録せず、管理マップに残したまま未確認とします。
4. 「カメラ画像に重ねたすべての区画位置が正しい」を確認してJSONを保存します。写真だけの場合は、従来必須だった地図と映像の4点対応は不要です。

**共通**：補正の下書きはそのブラウザの端末内に保存されます。研究用PCへの引き渡しは必ず **「確認済み設定JSONを保存」** でファイルを書き出してください。旧4点/多点JSONも読み込めます。写真の画角・取り付け位置・解像度が変わった場合は校正をやり直します。特に **マップで「画角外」指定した区画を写真の手動補正で勝手に監視対象へ戻すことはありません**。表示された区画IDが実際の場所と一致するか、先頭・中間・末尾の録画に重ねて検証してください。

### 対応点を増やした精密位置合わせ（2026-11-13）

「カメラと地図を合わせる」で **最初は地図と映像の対応点を最低4組** 指定します。
従来の4点のみの場合は以前と同じ射影変換です。ずれが残る場合は **5点目以降も追加** できます（最大24組、目安6～12組）。

1. 最初の4点は、画面の左上・右上・左下・右下のように、**地面上の白線・縁石の角**から離れた地点を選びます。
2. 5点目以降は中央や奥など、ずれが目立つ範囲に散らします。地図で点を選んだら、次は写真の**同じ地面上の場所**を選んでください。車の屋根・建物の上端は使いません。
3. 「全区画の位置を自動計算」を押します。5点以上では **RANSACによる外れ点の検出と、採用点の最小二乗推定** で位置を合わせます（4点固定には戻りません）。
4. 下の「対応点ごとのずれ・点の削除」で **平均位置誤差（RMS、画像ピクセル単位）** と各点のずれを確認します。赤く表示された点は「削除」して地図と画像の対応を選び直します。赤い点があるままではJSONを書き出せません。
5. 緑色の駐車枠すべてが正しい位置にあるか確認してから、JSONを保存します。書き出しには最大24点の対応座標と誤差診断を含み、研究用PCの `import_nikko_map_alignment.py` でも4～24組を検証して取り込みます。旧4点JSONも使えます。

**注意**：手書きで整えた模式図と実物の駐車場が同じ平面上の正確な縮尺とは限りません。対応点を増やしても、レンズ歪みや地図の形の違いによる残差が全区画で消えるとは限りません。部分的なずれは実動画で確認し、無理に不正確な区画を録画判定に含めないでください。画角外の区画は引き続きマップ上に残し、空き判定から除外します。

### カメラに映らない区画の管理

1. 管理者アプリで `道の駅日光（録画実験）` を選び、**映像に見える区画も見えない区画も**管理マップ上に登録して保存します。
2. 「カメラと地図を合わせる」画面の **「カメラに映らない駐車枠を指定」** を開き、画角外の区画にチェックを付けます。これはマップ内の `cameraCoverage: "outside"` として保存され、ユーザーアプリにも配信されます。
3. 動画から切り出した写真（1920×1080）を読み込み、マップと映像上の地面の4点を合わせて「全区画の位置を自動計算」を押します。**画角外の明示除外に加え、投影が枠外の区画も自動除外**されます。
4. 対象区画と対象外区画数を確認してJSONを書き出し、PCの起動メニューで「管理マップから画角内の区画を一括投影」から読み込んでください。
5. 実動画の先頭・中間・末尾の位置確認で一致する場合だけSを押します。**画角外の区画は管理マップに残りますが、YOLO判定・空き案内・録画の満空集計には含めません**。

**注意:** 現在のSupabase上の `nikko-test-001` マップは登録区画0件です。完成図を勝手に生成・上書きしないため、区画の正しい配置と番号を管理者アプリで設定する必要があります。画像上の枠と管理マップの対応を確認するまでは、全アプリへの案内開始をしないでください。

## 初回起動

研究用PCのPowerShellで更新してください。

~~~powershell
cd "$env:USERPROFILE\parking-guide-admin"
git pull --ff-only
~~~

parking-vision フォルダの「道の駅日光_録画YOLOを開始.cmd」をダブルクリックします。

1. PC内で再生・判定：クラウド通信なし（推奨）
2. 利用者アプリへ録画を共有：明示承認・ログインが必要
3. 全フレーム解析：コマを飛ばさないが再生速度が遅くなる場合あり

録画動画は未加工のMP4 / MOV / AVI / MKV / WebMを指定してください。YOLOの検出線を既に描き込んだ動画は再入力しないでください。原本を上書きしません。

PowerShellから直接実行する場合:

~~~powershell
cd "$env:USERPROFILE\parking-guide-admin\parking-vision"
powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\start_nikko_video.ps1 -Video "D:\動画\日光の元動画.mp4"
~~~

全フレーム解析には -AllFrames、1周で終了する場合には -Once、結果を利用者へ共有する場合には -Share を追加できます。未確認の区画を空きと決めつけず、動画冒頭の静止画で車や障害物がないと目視確認できる区画だけ、-VerifiedEmpty "space_001,space_004" のように指定してください。

## 方法A：管理マップから区画を一括位置合わせ（推奨）

1. 管理者アプリの「道の駅日光（録画実験）」を開く。初期のマップは空です。実際の駐車場を確認し、映像外も含めて区画・番号・位置・方向を登録する。
2. 元動画から1コマ静止画を用意する。例えば以下のFFmpegコマンドを使用する。

~~~powershell
ffmpeg -ss 1 -i "D:\動画\日光の元動画.mp4" -frames:v 1 "D:\動画\日光の位置合わせ.png"
~~~

3. 「カメラと地図を合わせる」を開き、カメラIDが nikko-recording-01 であることを確認する。
4. 静止画を読み込み、マップの床面とカメラ写真で同じ4点を指定する。
5. 位置合わせを行うと、映像内のすべての区画だけが投影され、「判定対象N区画／対象外M区画」と表示される。
6. 緑色の枠が実物と一致することを確認し、JSONを書き出す。
7. 上記の録画YOLO起動メニューで「管理マップから一括投影」を選び、そのJSONを指定する。
8. 元動画の先頭・中間・末尾に区画枠を重ねて表示するので、すべて正しい場合のみ各画面でSを押す。ずれている場合はQで中止する。

一度の位置合わせで全可視区画が生成されます。カメラが移動・パン・ズームする動画には、固定カメラ用の単一変換は使用できません。

## 方法B：動画に映る区画の四隅を手動登録

管理マップの位置合わせが難しい場合、起動メニューで「動画上ですべての区画の四隅を選んで登録」を選び、映っている区画数（1～999）を入力します。24件なら24件分の四隅をそれぞれ4クリックします。

管理マップの番号が飛んでいる場合は、IDを直接指定します。

~~~powershell
powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\start_nikko_video.ps1 -Video "D:\動画\日光の元動画.mp4" -SpaceUids "space_002,space_009,space_044" -Once
~~~

実際の管理マップの区画UIDと同じ番号を使ってください。画角外の区画は指定しません。別動画を使う場合は動画の指紋が一致せず、再校正を求めます。既存の校正を変更するときは、確認後にバックアップを取ります。

## 判定内容と出力

- 既定は元のFPSと同じ実時間ペース。推論が遅い時は一部フレームを飛ばします。
- 全フレーム解析では動画の時刻を進めて順に処理するため、低速PCでは実時間より再生が遅くなります。
- 出力されるのはYOLO判定付き動画、区画状態の変化CSV、車両・人物の追跡診断です。
- ループでは前周回の車両IDや占有状態を引き継ぎません。
- 動画冒頭の空き未確認区画は未確認とし、車両を検知した場合の入庫・停車・退出を追跡します。
- PCだけで動かす場合、データベースへは送信しません。

過去録画ビュー用CSVを生成する場合:

~~~powershell
python .\export_nikko_recording.py --config .\config_nikko_video_demo.json --video "D:\動画\日光の元動画.mp4" --log "D:\YOLO結果\区画状態の変化.csv"
~~~

生成された「駐車枠の状態_利用者アプリ用.csv」は管理者アプリの録画デモ欄から取り込めます。長い録画は共有リンク文字数の都合で分割する場合があります。

## 利用者アプリへの共有

録画共有モードでは、日光の録画実験用施設 nikko-test-001 にのみ情報を送ります。起動中だけ公開ON、停止時は公開OFFに戻します。利用者アプリは録画由来の新しい判定だけを受け取り、20秒以上古い状態を空きと認めません。

Supabaseに空の編集用マップと公開OFFの設定を準備しています。実際の道の駅日光の駐車枠は登録されていないため、管理者アプリで実物に沿った配置図を完成させないと、利用者アプリから区画の場所を案内できません。撮影範囲外の区画は空き案内・録画の集計から除外します。

## 制約

実際の道の駅日光の総駐車区画数・区画配置・録画映像は、この実装環境から確認できません。現地の映像と管理マップで必ず位置を検証してください。部分的にしか映らない区画は現在は対象外です。

CIで確認できるのは区画ID・マップ投影・録画同一性・前後周回・動画の時刻・利用者への録画と現在の空きの分離です。学習済みYOLOの本当の認識率は研究用PCで実映像を解析して評価する必要があります。
