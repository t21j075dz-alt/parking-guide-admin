# リアルタイムカメラの「再駐車しても出庫中のまま」を防ぐ

## 対象：研究の本番カメラ・USB Webカメラ・Camo

2026年11月9日の録画解析では「駐車区画＝停車中」「同一車両ID＝出庫中」という
状態不一致が見つかりました。録画実験にはreconcile_video_reparking.pyの
修正を導入済みです。リアルタイム側にも、次の2段階の改修を追加しました。

- VehicleTracker：一度出庫した同じ車が元の区画へ戻り、十分に停車した場合にも
  parkedへ戻す。従来の別区画への再駐車の動作は維持。
- LiveReparkingEvidence：リアルタイムの画像を使い、録画で使用した
  接地領域・安定車両ID・一定時間の停車を独立して再検証。通常の車両追跡で
  区画候補が確定しない場合でも、証拠が揃えば既存の出庫中IDを駐車中へ戻す。

**実カメラの空き確定は、従来のSpaceObserverが管理したままです。**
この機能は「空き」を勝手に生成せず、以前からある空き判定の安全条件も維持します。
録画との違いは、画像の時刻ではなくライブカメラの単調時刻を使用する点です。

## 安全条件

- 現在のフレームで見える監視対象・確認済み車両だけが対象
- 検出信頼度0.35以上
- 同じ安定車両IDで、同じ区画に十分長く停車したことが必須
- 通路を通過しただけ、停車未確定、検出消失だけなら変更しない
- 別の車と同じ区画を主張する場面、区画の重なりが曖昧な場面は変更しない
- 車両ID・セッションIDは継承し、新しい車両を捏造しない
- 駐車枠の現在の空き状態を録画用の状態機械から直接コピーしない

## 1. まずクラウド送信なしでリアルタイム確認

PowerShellで最新版を取得して実行します。

~~~powershell
cd "$env:USERPROFILE\parking-guide-admin"
git pull --ff-only
cd .\parking-vision

$researchPython = "$env:USERPROFILE\parking-yolo-home\.venv-gpu\Scripts\python.exe"

& $researchPython .\monitor.py --config ".\config.json" --preview --dry-run
~~~

この確認モードでは補正を自動的に有効にします。
画面とログに「リアルタイム再駐車補正：有効」が表示されます。
Supabaseには一切送信せず、車両が区画を出てから同じ区画・別区画へ
再駐車したときの状態を確認します。
映像の保存と診断CSVは従来どおりPC側で行われます。

## 2. 現地で検証して問題ない場合だけ、本番のクラウド連携へ

config.json内のJSONオブジェクトに次の行を追加します
（既存キーの末尾カンマが適切かを確認してください）。

~~~json
"live_reparking_sync_enabled": true,
~~~

PythonのJSON書式に合わせ、最後のキーなら末尾のカンマを消してください。
この設定を入れない場合、通常のカメラ本番実行には追加の補正を適用しません。
元のconfig.jsonのバックアップを手元に保存してから作業してください。

安全性を確認できなかった場合や誤検知が続く場合は、
値をfalseへ戻すことで補助判定を停止できます。
同じ区画への再駐車についてはVehicleTracker本体の安全な
停車確認（従来の安定区画投票）が通常動作として引き続き有効です。

## 3. 検証すること

- 入庫後、車両IDの状態と区画状態が双方とも駐車中になる
- 出庫後、元と同じ区画に戻って停車しても車両が出庫中のままにならない
- 出庫後、別の区画で停車しても以前の安定IDを継続する
- 車が区画を通過しただけでは駐車中にならない
- 隣接する2台の車を1台の車両IDに統合しない
- 車両が検出されなくなっても、区画を誤って空きにしない

今回の改修のテストはGPU不要な仮想データによる回帰テストです。
リアルタイムの現場カメラ映像による実測・本番の駐車案内精度は、
研究PCと現場のカメラで確認するまで未検証です。

## 研究上の根拠となる既存コード

- monitor.py / Vehicle.observe：時間的な停車判定と継続する安定ID
- recorded_parking_states.py：車体下端付近の接地領域による駐車枠推定
- reconcile_video_reparking.py：録画用の同一車両ID／停車一致確認
- reconcile_live_reparking.py：リアルタイム用の追加証拠チェック
- tests/test_live_reparking.py：通過・他車・低信頼度・同じ区画への戻りの回帰テスト
